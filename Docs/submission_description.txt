For Week 1 I built a Unity 6 scene called Hillside Village Overlook, using Unity 6000.4.7f1 on the Built In Render Pipeline. The scene is an enclosed valley containing a sculpted terrain, a village of eleven houses strung along a curving dirt road, forested slopes rising into bare rocky peaks, a lake in a carved basin, a campsite and parked vehicles. It contains 954 objects in total: 420 trees, 130 rocks, 300 ground details, eleven buildings, six vehicles and a campsite cluster.

The terrain is a 400 by 400 unit heightmap generated from layered Perlin noise, with a village plateau flattened into it, a lake basin carved below, and the map edges lifted into a surrounding ridge so the terrain boundary is never visible from inside the valley. Four terrain layers are blended by altitude and slope, so grass gives way to dry grass and then to exposed rock on the steep faces, and a dirt road is painted directly into the splatmap so it follows the road curve exactly.

For imported assets I used four free CC0 packs from Kenney.nl: the Nature Kit, City Kit Suburban, Survival Kit and Car Kit. That is four distinct sources against the required minimum of three. All four are public domain, so there are no licensing restrictions, and full attribution with source URLs is recorded in the project. I imported only the 82 models the scene actually places, out of 499 available, and only in FBX format, to keep import times and repository size down.

Assets are organised with first party work under Assets/_Project and all downloaded content quarantined under Assets/ThirdParty, so the two never mix. Scripts are split into Editor and Runtime folders, which is functional rather than cosmetic, because Unity excludes anything in an Editor folder from builds.

Lighting is realtime: a low afternoon directional light with soft shadows, a procedural skybox, Trilight ambient so shadowed faces pick up skylight instead of going black, and linear fog for aerial perspective.

Rather than placing 954 objects by hand, I wrote an Editor tool, SceneBuilder.cs, that generates the entire scene deterministically from a fixed random seed. This makes the scene reproducible, reviewable as source code, and adjustable by changing a constant and rebuilding. The README documents the folder conventions, asset licensing, lighting choices, and four real bugs I hit and fixed, including a splatmap that computed correct values but silently failed to persist because I painted it before the terrain asset was created.
